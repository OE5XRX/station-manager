{% comment %} Firmware update status of one module (update_status.UpdateStatus). Expects `module` and `status`. Optional flags: - `compact`: short label, full reason as tooltip (module list, station card). Without it (module detail) the full reason line sits next to the pill. - `nopoll`: never poll (module list: a reload is enough). - `card`: station card. Always polls: every 5 s while live, otherwise every 30 s, plus right away on the `fw-status-refresh` body event that control-panel.js fires when a module leaves the live flash state. A card on an open control panel must never freeze on a pre-flash or settled state. - `can`, `csrf_token`: the detail variant (neither compact nor card) renders the "Erneut versuchen" form for a failed module to modules.manage users, so a poll that lands on "Fehler" brings the button along without a reload. Outside the card, the root element re-fetches itself every 5 s only while the state can still change on its own (status.is_live); a settled state renders without hx-* attributes, so the polling stops by itself. Every polling pill carries data-poll-visible-only: app.js cancels its requests while the tab is hidden, so a background tab (WAITING can last days) never keeps the rolling session alive. No htmx trigger filter: htmx evals those via Function(), which fails open under a CSP without unsafe-eval. {% endcomment %} {% with s=status.state %} {% if s != 'no_target' %}{% endif %}{% if compact and s == 'running' %}{{ status.reason_text }}{% else %}{{ status.short_label }}{% endif %} {% if not compact and status.reason_text != status.short_label %}{{ status.reason_text }}{% endif %} {% if not compact and not card and s == "failed" and can.modules.manage %}
