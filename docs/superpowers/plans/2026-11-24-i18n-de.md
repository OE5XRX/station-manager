# Deutsche Lokalisierung — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Steps use `- [ ]`.

**Goal:** Wer „DE“ wählt (oder `User.language=de` hat), sieht die komplette UI auf Deutsch — ohne
Zahlen-/Datums-Regressionen.

**Spec:** `docs/superpowers/specs/2026-11-24-i18n-de-design.md`

**Basis:** `origin/main` @ `be1ed39`, Branch `feat/i18n-de`.

## Global Constraints

- Tests: `DJANGO_SECRET_KEY=x .venv/bin/python -m pytest -q <files>` (Settings `config.settings.test`).
- Gates vor jedem Commit: `.venv/bin/ruff format --check . && .venv/bin/ruff check . &&
  .venv/bin/python scripts/check_template_comments.py && .venv/bin/python scripts/check_color_tokens.py`.
- Django-Templates: **kein mehrzeiliges `{# … #}`**, nur `{% comment %}`.
- Neue Templates-Strings mit `{% translate %}` / `{% blocktranslate %}` (bestehende `{% trans %}` bleiben).
- Quellsprache aller msgids = Englisch.
- `.mo` nie committen. `locale/de/LC_MESSAGES/*.po` werden nur über `scripts/i18n.sh make` erzeugt/aktualisiert.
- TDD: erst roter Test, dann Code.
- Keine Änderung an OIDC-Pfaden außerhalb `i18n_patterns`.

## Task 1 — Build-/CI-Infrastruktur

- [ ] `scripts/i18n.sh` (bash, `set -euo pipefail`, `PYTHON` env-überschreibbar, default `python`):
  - `make`: `makemessages -l de --no-obsolete` (Domain django; Ignores: `.venv/* vendor/* staticfiles/*
    tests/* station_agent/* docs/* scripts/* node_modules/*`) und `makemessages -d djangojs -l de
    --no-obsolete` mit denselben Ignores (JS liegt in `static/` und `apps/*/templates/**/*.js`).
  - `compile`: `compilemessages -l de` mit denselben Ignores.
  - `check`: `make`, dann für beide `.po`: `msgattrib --untranslated --no-obsolete` und
    `msgattrib --only-fuzzy` → nicht leer = Fehler mit Liste der msgids + Hinweis
    „run scripts/i18n.sh make and translate“; dann `compile`. Zusätzlich `git diff --exit-code -- locale/`
    NICHT (Zeilennummern-Churn) — nur die msgattrib-Checks.
- [ ] `.gitignore`: `*.mo`.
- [ ] Dockerfile: nach `COPY . .` ein `RUN apt-get update && apt-get install -y --no-install-recommends gettext
  && DJANGO_SECRET_KEY=... python manage.py compilemessages -l de --ignore ... --settings=config.settings.prod
  && apt-get purge -y --auto-remove gettext && rm -rf /var/lib/apt/lists/*` (vor `collectstatic`).
- [ ] CI `ci.yml`: neuer Job `translations` (ubuntu, Python 3.14, `pip install -r requirements/dev.txt`,
  `apt-get install gettext`, `PYTHON=python scripts/i18n.sh check`); im `test`-Job `gettext` mit in die
  apt-Liste und vor `pytest` `scripts/i18n.sh compile`; Postgres-Job analog, falls er UI-Strings prüft
  (sonst nicht nötig).
- [ ] `tests/conftest.py`: session-autouse Fixture `_compiled_translations` — kompiliert per
  `call_command("compilemessages", ...)`, wenn eine `.po` neuer ist als ihre `.mo` oder `.mo` fehlt;
  wenn `msgfmt` fehlt: `pytest.exit` mit klarer Meldung? Nein → `warnings.warn` + weiter (Tests, die DE
  brauchen, schlagen dann sichtbar fehl).
- [ ] Settings `prod.py`: `LANGUAGE_COOKIE_SECURE = True`, base: `LANGUAGE_COOKIE_HTTPONLY = True`,
  `LANGUAGE_COOKIE_SAMESITE = "Lax"`, `LANGUAGE_COOKIE_AGE = 365 * 24 * 3600`.

## Task 2 — Sprache ↔ User

- [ ] `apps/accounts/language.py`: `apply_user_language(response, request, language, next_url=None)` —
  setzt Cookie (`settings.LANGUAGE_COOKIE_*`) und gibt optional `translate_url(next_url, language)` zurück;
  Validierung gegen `settings.LANGUAGES`.
- [ ] `LoginView.form_valid`: Response von super holen; bei Redirect `Location` via `translate_url` auf
  `user.language` umschreiben; Cookie setzen.
- [ ] View `accounts.views.set_language` (`@login_not_required`, POST only): ruft
  `django.views.i18n.set_language`; wenn `request.user.is_authenticated` und Sprache gültig → `User.language`
  speichern (`update_fields`). URL **außerhalb** `i18n_patterns` (`/i18n/setlang-user/` o.ä. — oder in
  `config/urls.py` vor `django.conf.urls.i18n` als `i18n/setlang/` registrieren, damit der bestehende Pfad
  und die `LoginRequiredMiddleware`-Allowlist weiter passen; bevorzugt: denselben Pfad überschreiben).
  Topbar-Formular unverändert lassen, wenn der Pfad gleich bleibt.
- [ ] Profil `_save_identity`: wenn `language` in `changed_data` → Cookie + Redirect auf
  `translate_url(reverse("accounts:profile"), new)`.
- [ ] `config/middleware.py: UserLanguageMiddleware` (nach `AuthenticationMiddleware`, vor
  `LoginRequiredMiddleware` egal — nach Auth): Bedingungen laut Spec; Settings-Eintrag.
- [ ] Tests `tests/test_i18n_user_language.py`: alle Fälle aus der Spec.

## Task 4 — Zahlen/Daten unter `de` absichern

Audit (2026-11-24): kein `USE_THOUSAND_SEPARATOR`, keine Date/DateTime-Widgets, kein `localize=True`,
kein `django.utils.formats` in Python. Bereits abgesichert: `widgets/_number.html`, Monitoring-Thresholds,
`metric_definitions.html`, `alert_settings.html`. Reine Anzeige (Komma ist dort gewollt): Koordinaten/Höhe
in Stations-/User-Detail, Temperatur, `|date:"d M H:i"`, `timesince`.

- [ ] `apps/control/templates/control/widgets/_telemetry.html:9-10`: `data-min`/`data-max` in
  `{% localize off %}` (JS `control-logic.parseNumber` toleriert zwar ein Komma, aber Regel ist Regel).
  Test: Telemetrie-Widget mit Float-Range unter `de` gerendert → `data-min="0.5"`.
- [ ] `apps/stations/forms.py:35-39` (latitude/longitude/altitude/tx_audio_ceiling_dbfs): `lang="en"` an die
  NumberInputs (Projekt-Regel DE-Locale Number-Inputs). Test: Feld-HTML enthält `lang="en"`.
- [ ] Generischer Scan-Test `tests/test_i18n_locale_formats.py`: rendert unter `/de/` Dashboard,
  Stationsdetail (mit Float-Koordinaten + Metriken), Control-Panel (mit Float-Widget-Range), Monitoring-
  Alarmeinstellungen/Metrikdefinitionen und scannt alle Attribute `value|data-[\w-]+|min|max|step|style`
  auf `\d,\d` → Fehlschlag mit Attribut + Seite.
