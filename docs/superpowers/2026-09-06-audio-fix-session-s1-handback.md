## RC#2 — Agent broker robustness (BLOCKER-class)

### Evidence / root cause

- Live symptom: `[ERROR] station_agent.broker: execute error … slot 1000 module audio-router cap streams` + `TypeError: open: path should be string, bytes or os.PathLike, not NoneType`, ~1×/s.
- The prod QEMU station runs the SRCREV pinned in `linux-image` = `2c80f96` = current `main`, so the crash is reproducible against HEAD.
- The log string matches `broker.py` `_poll_loop` exactly. Trace:
  - Server subscribes the `audio-router` `streams` telemetry cap on synthetic slot **1000**.
  - `_poll_loop` calls `_execute(1000, "audio-router", "get", "streams", None)` every poll tick.
  - `_execute` did `self._transport_factory(self._control_path(1000))`. `_control_path(1000)` → `self._controls.get(1000)` → **`None`** (virtual modules carry no control device).
  - Default factory builds `SlotControl(None)`; `SlotControl.execute` → `os.open(None, …)` (`slot_control.py:88`). `os.open(None)` raises **`TypeError`** — the surrounding `except OSError` does **not** catch it — so it escapes to `_poll_loop`'s `except Exception`, which logs the observed error once per tick.
- `list_audio_slots()` on HEAD has **no `open()`** at all and is already robust to foreign untagged cards (existing `test_list_audio_slots`), confirming the prompt's hypothesis was a red herring.

### Fix

`station_agent/broker.py`: `_execute` now diverts virtual modules to a new `_execute_virtual(vm, capability)` **before** any serial transport is built. `_execute_virtual` snapshots `vm.state()` off the event loop (via executor — `state()` may shell out to PipeWire/udev), returns `{"ok": True, "value": state[cap]}`, and fails closed (`unknown_capability` / `validation_failed`) so the poll loop simply skips. This mirrors the two paths that already special-cased virtual modules (`handle_command` line ~174, `emit_inventory` line ~241) — the telemetry poll was the third, missing divert point.

### Defense-in-depth (as requested)

`station_agent/audio/router_backend.py`: `_card_indices()` and `_card_id()` now fail closed (`[]` / `None`) when `_sysfs_sound` is falsy, so no code path can ever `os.path.join(None, …)` or `open(None)`. Foreign untagged sound cards were already skipped (only `OE5XRX_SLOT`-tagged cards are returned); a regression test now locks that in explicitly alongside a missing-`id`-attribute foreign card.

### Tests

- `tests/test_broker_virtual_telemetry.py` (new):
  - `test_virtual_telemetry_poll_never_builds_a_transport` — spy factory raises if called; asserts it is never called for the virtual slot (directly proves the `os.open(None)` path is gone).
  - `test_virtual_telemetry_poll_emits_state_value` — asserts the poll emits the router's real `streams` state.
- `tests/test_audio_router_backend.py` (added):
  - `test_foreign_untagged_card_is_skipped_and_does_not_crash`
  - `test_resolve_ignores_foreign_card_node`

## FIX #3 — `audio_enabled` rollout

### Investigation: how station config.yml is generated/delivered

- Generated by `apps/provisioning/config_render.py::render_config(...)`, called from the `run_background_jobs` management command during a **ProvisioningJob** (`apps/provisioning/management/commands/run_background_jobs.py`).
- Injected into the image's `/etc-overlay/stationagent/config.yml` via `guestfish.inject_provisioning_files` at bundle-build time.
- **There is NO config-push to running stations.** config.yml is written once, at provisioning, and is a **CONFFILE preserved across OTA**. The agent reads it at startup via `station_agent/config.py::load_config()`.
- Before this fix, `render_config` never emitted `audio_enabled`, so the agent used its default `audio_enabled=False` → "Audio channel disabled" → the audio engine + `audio-router` virtual module were never started.

### Chosen approach (minimal, per-station opt-in)

- New `Station.audio_enabled = BooleanField(default=False)` (`apps/stations/models.py`, migration `0017_station_audio_enabled`), editable in the Django admin "Hardware" fieldset. **Not** on any non-admin form/serializer (verified by the security review) — admin is the authorization boundary, consistent with other hardware fields.
- `render_config(..., audio_enabled: bool = False)` emits `audio_enabled: true|false` (fixed literal — no user string reaches the YAML). `run_background_jobs` passes `job.station.audio_enabled`.
- Default `False` is deliberate: FM is the only audio hardware that exists today (Spec 0 §1), most stations have none, so audio is opt-in per station.

### Rollout for EXISTING stations

Because config.yml is a preserved CONFFILE and there is no config-push:

1. **Re-provision (supported path):** admin sets `audio_enabled` on the Station → create a new ProvisioningJob → download + flash the new bundle. The regenerated config.yml carries the flag.
2. **Manual on-device edit (one-off/debug only):** edit `/etc/stationagent/config.yml`, set `audio_enabled: true`, restart the agent. Not a fleet rollout (and no SSH-based deploy per project convention) — use only for a single dev/bench box.
3. **Future work (not built):** a control-plane config-push / `reconfigure` command so a flag flip reaches running stations without a re-flash. Out of scope here.

The model `help_text` surfaces the re-provisioning caveat in the admin UI.
